# Граф денег — HackAlem AI

Анализ транзакционного графа: построение сети переводов, определение роли
каждого узла в сети и разбиение сети на кластеры (группы связанных узлов).

## Данные

Данные лежат в `data/` и обезличены. Граф построен на 4 колена (глубины)
от seed-узлов.

| Файл | Описание |
|---|---|
| `nodes.parquet` | `gid`, `depth`, `is_seed` — все узлы графа |
| `edges.parquet` | `src`, `dst`, `sum_kzt`, `n_tx`, `depth` — агрегированные рёбра |
| `transactions.parquet` | отдельные транзакции, из которых агрегированы `edges` |

Размер графа: 2248 узлов, 3119 рёбер.

## Установка

```bash
pip install pandas numpy networkx pyarrow scipy
```

## Запуск

```bash
python starter.py --data data --out out
```

На выходе в папке `out/` появятся три файла:

- **`nodes_roles.csv`** — роль каждого узла (`role`, `role_score`, `evidence`),
  его `cluster_id`, `priority_score` и базовые графовые метрики (степени,
  обороты, PageRank).
- **`clusters.csv`** — сводка по кластерам сети.
- **`top_nodes.csv`** — топ-20 узлов по `priority_score`.

## Роли узлов

Роль определяется структурными признаками узла в графе (степени, PageRank,
соотношение входящих/исходящих сумм). Ни одна роль не является утверждением
о личности клиента или незаконной деятельности — это статистическая гипотеза.

| Роль | Признак |
|---|---|
| `coordinator` | высокий PageRank + есть и входящие, и исходящие связи |
| `distributor` | отправляет деньги большому числу разных получателей |
| `consolidator` | получает деньги от большого числа разных плательщиков |
| `transit` | сумма полученного ≈ сумма отправленного дальше (pass-through ≈ 1) |
| `terminal` | нет исходящих связей, но узел НЕ на границе глубины графа (depth < 4) |
| `peripheral` | не попал ни в одну из категорий выше |

Важный нюанс: узел на `depth = 4` без исходящих связей — это не обязательно
`terminal`, а может быть точкой, где просто закончился обход графа (глубина
ограничена 4 коленами). Такие узлы помечены `truncated_by_depth = True` и
не считаются `terminal` автоматически.

## Кластеризация

Реализована в отдельном модуле `clustering.py`, независимом от `role` и
`priority_score` — чтобы изменения в логике ролей не влияли на кластеризацию,
и наоборот.

- **Алгоритм**: Louvain community detection (`networkx.community.
  louvain_communities`) на неориентированной проекции графа, с учётом весов
  рёбер (`sum_kzt`).
- **Воспроизводимость**: фиксированный `seed=42` — результат детерминирован
  между запусками на одних и тех же данных.
- **Узлы без единого ребра** (в датасете таких 19) получают собственный
  уникальный `cluster_id`, а не сваливаются в общий кластер.

### Колонки `clusters.csv`

| Колонка | Что означает |
|---|---|
| `cluster_id` | идентификатор кластера |
| `n_nodes` | число узлов в кластере |
| `n_seed` | из них — с `is_seed = True` |
| `sum_kzt_internal` | сумма `sum_kzt` по рёбрам, у которых и `src`, и `dst` — в этом кластере |
| `top_gids` | до 5 самых значимых узлов кластера по PageRank |
| `hypothesis` | короткая структурная гипотеза о кластере (доля seed, доля внутренних связей, размер) — не утверждение о личности или преступной деятельности |

## Структура репозитория

